# Architectural Guide: Quality Pillars & Prioritized Backlog Framework

This document describes the design, taxonomy mapping, and validation gates for the **Quality Pillars & Prioritized Backlog Framework** configured in `repo-wizard`.

---

## 1. Architectural Overview

To organize the recommendations generated by a diverse workforce of specialist agent personas, `repo-wizard` establishes a unified **Quality Pillar** taxonomy. Rather than assigning arbitrary numeric grades or scorecards to codebases, the system groups specialist findings into five engineering-centric quality pillars:

1. **Security & Compliance**: Focuses on data safeguards, dependency compliance, and legal liability mitigation.
2. **Performance & Resilience**: Focuses on latency thresholds, system scalability, instrumentation, and stability.
3. **Architecture & Design**: Focuses on modular boundaries, schema validation, and system specifications.
4. **Code Quality & Testing**: Focuses on static analysis discipline, test coverage, and state hygiene.
5. **System Orchestrators & Helpers**: Handles coordination utilities and workflow automation.

By categorizing agent findings under these pillars, the system provides developers with a clear and structured view of their codebase's health, facilitating focused and effective improvements.

---

## 2. Taxonomy Mapping & Configuration

The framework separates the definition of the Quality Pillars from the active specialist registry:

* **Pillar Type Definitions (`scripts/quality-pillars.js`)**: Encapsulates the pillar enums and display names in a single, zero-dependency constant module to avoid inline string duplication.
* **Agent Mappings (`agents/agent-quality-pillar-mappings.json`)**: Map each of the 27 specialized agent personas to exactly one Quality Pillar.

```
                           +----------------------------------------+
                           |  agent-quality-pillar-mappings.json    |
                           +-------------------+--------------------+
                                               |
                                               | Loads Mappings
                                               v
     +-----------------------------------------+-----------------------------------------+
     |                                                                                   |
     v                                                                                   v
+----+----------------------------------+                           +--------------------+------------------+
|  scripts/validate-agents.js           |                           |  scripts/reports-compile.js           |
|  (Pre-commit Validation Gate)          |                           |  (Report & Backlog Generation Engine) |
+----+----------------------------------+                           +--------------------+------------------+
     |                                                                                   |
     | Verifies all registered agents                                                    | Group reports by pillar;
     | are mapped in taxonomy                                                            | assigns backlog effort labels
     v                                                                                   v
+----+----------------------------------+                           +--------------------+------------------+
|  Passes commit / Aborts commit        |                           |  Full Report (HTML & Markdown)        |
+---------------------------------------+                           |  Backlog CSV (with Effort vs. Value)  |
                                                                    +---------------------------------------+
```

---

## 3. Pre-Commit Validation Gate

To verify that new agent personas are properly integrated into the quality pillars framework upon addition, the pre-commit hook runs `validate-agents.js`. 

This validation script:
1. Scans the `agents/` directory to identify all registered agent personas.
2. Reads `agents/agent-quality-pillar-mappings.json`.
3. Verifies that every active agent has a corresponding pillar mapping defined.
4. Halts the commit sequence with an exit code of `1` if any unmapped agent is discovered, maintaining taxonomy integrity.

## 4. Prioritized Backlog & Effort-Value Matrix

Findings compiled into the tabular backlog (`backlog.csv`) are mapped to priority labels based on their technical impact and implementation complexity:

| Classification | Effort | Value / Impact | Description |
| :--- | :--- | :--- | :--- |
| **Quick Win** | Low | High | Minimal setup friction; provides immediate safeguard benefits. |
| **High-Value Project** | High | High | Core reliability or performance integration; requires dedicated development cycles. |
| **Quality of Life** | Low | Low | Documentation, helper diagrams, or minor workspace enhancements. |
| **Strategic Debt** | High | Low | Long-term refactoring or non-blocking structural goals. |

The orchestrator writes these effort-value classifications directly as labels in the backlog files, enabling teams to schedule tasks asynchronously according to their active bandwidth.
