# Implementation Plan: Comprehensive Decoupling of Static Report Text and Backlog Data

This plan refactors the report compiler engine to remove all remaining hardcoded strings, including those in the Full Technical Report (preamble, maturity guidance, conclusions), the Observations Summary (suggested adjustments), and the Backlog CSV stories (`backlog.csv`). All deliverables will be populated dynamically from fields generated by the AI orchestration agent and stored within the session state.

---

## Proposed Changes

### [Compiler Engine]
#### [MODIFY] [reports-compiler-engine.js](../scripts/reports-compiler-engine.js)
* **Remove Static Stubs**:
  * Delete all hardcoded string templates for `sec1Text`, `sec2Text`, `sec3Text`, `maturityGuidance`, and `conclusionText`.
  * Delete the hardcoded bullet points under the "Suggested Adjustments" section in the Observations Summary.
  * Delete the hardcoded `stories` array (located in [reports-compiler-engine.js:L483-592](../scripts/reports-compiler-engine.js#L483-L592)) that statically writes stories to `backlog.csv`.
* **Dynamic Content Extraction**:
  * Extract the Executive Summary sections from `session.customReport.section1`, `session.customReport.section2`, and `session.customReport.section3`.
  * Extract the Maturity Model Guidance from `session.customReport.maturityGuidance`.
  * Extract the Conclusions from `session.customReport.conclusion`.
  * Extract the Suggested Adjustments from `session.customReport.suggestedAdjustments`.
  * Extract the backlog items from `session.customReport.backlog` (an array of objects).
  * Allow optional override of the Full Report Preamble via `session.customReport.preamble` (falling back to a neutral default if omitted).
* **New Subsection: Interview Profile**:
  * Under Section 2 of the Full Technical Report ("Audit Scope & Environment Profile"), add a subsection dynamically checking `session.answersInferred`:
    * If `session.answersInferred === true`:
      * Title: `### 2.1 Inferred Interview Profile`
      * Note: `*Note: The survey answers in this profile were dynamically inferred by the Repo Wizard orchestration agent using best-guess codebase sweeps rather than user input.*`
    * Else:
      * Title: `### 2.1 Interview Profile`
      * (No inferred notice)
    * Render a list/table of all questions and selected/inferred answers dynamically extracted from the `session.answers` map.
* **Robust Error Handling**: If the `customReport` object or its required keys are missing from the `session` object, raise a descriptive error indicating that compilation cannot proceed because the dynamic custom report text has not been written by the orchestration agent yet.

---

### [Orchestration Agent Configuration]
#### [MODIFY] [repo-wizard-agent.md](../agents/repo-wizard-agent.md)
* **Instruct Custom Summary & Backlog Generation**: Update the agent instructions (under Steps 5 and 6) to explicitly mandate that the agent must:
  1. Read the observations generated by the specialist subagents.
  2. Read the specialist agent-to-pillar mappings directly from [agents/agent-quality-pillar-mappings.json](../agents/agent-quality-pillar-mappings.json) to align all observations, summaries, and backlog tasks under the **4 Core Quality Pillars**:
     * **Security & Compliance**
     * **Performance & Resilience**
     * **Architecture & Design**
     * **Code Quality & Testing**
  3. Synthesize custom, bespoke Executive Summary sections (Section 1: Codebase Health & Strengths, Section 2: Tooling & Compliance Opportunities, Section 3: Rollout Roadmap), Maturity Model Guidance, Suggested Adjustments, and Conclusion text.
  4. Format these sections according to the layout and validation checks:
     * Paragraph 1: Italicized summary (BLUF), without the literal "BLUF:" prefix.
     * Paragraph 2: High-level overview, starting with the literal "Overview:" prefix.
     * Technical Overview paragraphs: Each must contain between 3 and 6 sentences, with a total section word count between 800 and 3000 words.
  5. Generate a custom backlog task list representing the actual suggested actions compiled from the specialist audits, categorized under the 4 pillars.
  6. Set `session.answersInferred` to `false` (interactive mode) or `true` (headless mode).
  7. Write this generated content as a `customReport` JSON object directly into the `.repo-wizard/session.json` state file before running the compilation command.
